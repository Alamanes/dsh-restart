# dsh-restart

一次性彻底关闭并重新启动 DSH 桌面应用，省掉「切换插件 → 手动退出 → 重新打开」那套动作。用于调试无法热重载的插件：新装的插件、改了客户端 bundle 的插件、改了 profile patch 的情况。

## 两个入口

| 入口 | 位置 | 说明 |
|---|---|---|
| 重启按钮 | 会话标题栏右上角 | 点击即走，不弹任何确认 |
| `restart_dsh` 工具 | 模型自主调用 | 与按钮同一套流程 |

## 重启时正在运行的会话

重启前插件会记下**其他**正在运行的会话（发起重启的那个会话不算），重启后自动 `resume` 它们并投递一句用户消息「继续工作。」，让被中断的工作接着做。

会话清单写在 `~/.dsh/dsh-restart/pending.json`，下一次启动读取后立即删除，所以只有真正被重启中断的那批判会恢复一次。

## 重启方式

宿主插件跑在桌面应用的 host 子进程里，窗口与单实例锁属于 Electron 主进程，因此重启交给一个 detach 出去的 shell 脚本：

1. 等待 0.4 秒让 HTTP 响应先送达；
2. `TERM` 主进程，最多等 5 秒，再 `KILL`；
3. 回收 host 子进程与残留 Helper；
4. `open -a` 重新打开应用。

先杀主进程是刻意的：反过来会触发桌面端的崩溃恢复弹窗。

## 限制

- 只在 DSH 桌面应用里可用（`ELECTRON_RUN_AS_NODE=1` 且可执行文件在 `.app` 包内）。`dsh web` / `dsh tui` 这类从终端起的进程没有可重开的 app 包，按钮会报「当前不是桌面应用宿主」。
- 重启会立即中断发起重启的那个会话的本轮回复。

## 安装

```json
{
  "dependencies": {
    "dsh-restart": "github:Alamanes/dsh-restart"
  },
  "dsh": {
    "profile": {
      "bundles": ["dsh-restart"]
    }
  }
}
```

装完需要重启一次 DSH 才会生效——这正是本插件存在的理由。

## 文件

| 文件 | 作用 |
|---|---|
| `lib/index.js` | 宿主半边：路由、`restart_dsh` 工具、重启脚本、重启后恢复 |
| `lib/client.js` | 浏览器半边：右上角按钮 |
| `cordis.patch.yml` | 插件挂载声明 |
